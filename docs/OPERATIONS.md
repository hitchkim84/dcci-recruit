# 관리자 운영 방법 · 배포 · 복구

## 1. 권한
| 등급 | 로그인 | 할 수 있는 일 |
|---|---|---|
| 슈퍼관리자(`admin`) | 이메일 + 비밀번호(16자 이상) + 인증 앱 OTP | 공고·지원서·전형·결과 공개·삭제·공지/FAQ·담당자 계정·설정·기록·파기 전부 |
| 일반 담당자(`staff`) | 아이디 + 비밀번호(12자 이상), OTP 없음(확정된 운영 조건) | **지정된 공고**의 지원자 목록·상세·첨부 열람·CSV 다운로드만 |

화면에서 버튼을 숨기는 것과 별개로 서버(`netlify/functions/admin.js`)와 DB 함수(`sql/04_admin.sql`)가 같은 기준으로 막는다.
로그인 정보는 브라우저 탭 안에만 남고, 30분 동안 조작이 없으면 자동 로그아웃된다.

## 2. 채용 진행 순서 (슈퍼관리자)
1. **[채용공고] → 새 공고 등록**: 제목, 접수 시작·마감(한국 시간), 모집 분야·인원·업무, 공고 내용(확정된 내용만), 지원서 항목(생년월일·주소·병역, 학력·경력·자격 받기/필수, 자기소개 문항·글자 수, 첨부서류), 제출 후 수정·취소 허용 여부, **동의문**, **보관기한**, 담당자 지정 → 저장(초안).
   - 동의문이 비어 있으면 지원자가 제출할 수 없다. '기본 문안 넣기'는 `[검토 필요]` 문안이므로 확정 후 표시를 지운다.
   - 보관기한이 비어 있으면 자동 파기되지 않는다(업무 기준 확정 후 입력).
2. 홈페이지 [보기]로 확인 → **[게시]**. 접수 기간이 되면 '접수 중'으로 바뀐다(서버 시각 기준).
3. 접수 중: [지원자] 탭에서 제출된 지원서를 조회(임시저장은 목록에 나오지 않고 개수만 표시).
4. 마감: 마감 시각이 지나면 자동으로 접수가 막힌다. 급히 멈출 때는 **[마감]**.
5. 전형: [지원자] → 체크 → 단계 선택 → **[단계 변경]** (지원자에게는 아직 안 보임) → 확인 후 **[결과 공개]**. 공고의 '결과 안내' 문구가 함께 보인다. 공개 후 단계를 바꾸면 다시 [결과 공개]를 눌러야 반영된다.
6. 채용 종료 후: **[보관]**(홈페이지에서 숨김). 보관기한이 지나면 지원서·첨부파일이 매일 03:10 자동 파기된다.

### 지원자 탭
- 검색(이름·접수번호·이메일·전화 일부), 전형 단계 필터, **[상세]**(전체 지원서·첨부 열기·처리 기록), **[인쇄 / PDF 저장]**(브라우저 인쇄에서 'PDF로 저장').
- **[CSV 다운로드]**: 엑셀에서 열 수 있다. 수식으로 시작하는 값은 앞에 `'`가 붙는다(수식 실행 방지). 내려받은 파일은 업무 후 지운다.
- 첨부 열기 주소는 60초 동안만 유효하다.
- **[선택 삭제]**(슈퍼관리자, 최대 100건): 확인 창 + '삭제' 입력 후 지원서와 첨부파일을 함께 삭제. 되돌릴 수 없다.
- 조회·상세·다운로드·첨부 열람·변경은 모두 [기록·파기] 탭의 활동 기록에 남는다.

### 담당자 계정 탭
- 직원마다 개인 계정(공용 계정·공용 비밀번호 금지). 아이디·비밀번호(12자 이상) 입력 → 만들기 → [채용공고] → [수정] → 담당자 지정.
- 퇴사·이동 시 **즉시 삭제**. 비밀번호 분실 시 [비밀번호 변경].

### 설정 탭
- 문의처(바닥글), 전형 절차 안내, 개인정보처리방침, 기본 동의문, 관리자 기록 보관 일수. 비운 항목은 홈페이지에 표시하지 않는다.
- `검토 필요` 표시 항목은 법무·개인정보 담당 확인 후 입력한다.

### 기록·파기 탭
- 자동 파기 실행 결과(지원서 삭제 수, 파일 삭제·실패 수, 남은 파일). '확인 필요'가 보이면 [지금 실행]으로 다시 시도하고, 계속되면 Netlify Functions 로그를 확인한다.
- 관리자 활동 기록: **월 1회** 열람해 낯선 계정·시간대·대량 다운로드가 없는지 확인한다.

## 3. 운영 점검표 (운영 확인 — 실제 Supabase·Netlify에서만 가능)
처음 운영 전, 그리고 설정을 바꾼 뒤 한 번씩 확인한다. 테스트 공고 제목에는 `[테스트]`를 붙이고 끝나면 지운다.
- [ ] 지원자: 실제 메일로 인증코드 수신(스팸함 포함), 틀린 코드 거절, 로봇 확인 위젯 표시
- [ ] 지원자: 임시저장 → 탭을 닫고 다시 인증 → 내용 복구
- [ ] 지원자: PDF 업로드 성공, 확장자만 바꾼 파일 거절, 10MB 초과 거절
- [ ] 지원자: 제출 → 접수번호, 지원내역에 '제출 완료'
- [ ] 다른 이메일로 인증한 사람에게 위 지원서가 보이지 않음
- [ ] 슈퍼관리자: OTP 없이 로그인 시도 시 관리 화면 진입 불가
- [ ] 일반 담당자: 지정 공고만 보이고, 다른 공고·수정 기능 없음
- [ ] 첨부 [열기] 주소를 복사해 **1분 뒤** 열면 거절되는지(만료)
- [ ] Supabase Storage 대시보드에서 `applicant-files` 버킷이 Private인지
- [ ] `sql/check_security.sql` 결과에 '확인 필요' 없음(보관기한 미입력 제외)
- [ ] 다음 날 [기록·파기]에 자동 실행 기록이 생겼는지

## 4. 배포
- 작업 브랜치에서 수정 → 테스트(`npm test`, SQL을 바꿨으면 `npm run test:db`, 화면을 바꿨으면 `npm run test:e2e`) → PR → 확인 후 `main`에 머지하면 Netlify가 바로 운영에 배포한다.
- 배포는 모아서 한 번에(Netlify 크레딧 절약).
- SQL 변경은 `sql/`에 번호를 붙인 새 파일로 추가하고, 여러 번 실행해도 안전하게 작성한 뒤 Supabase SQL Editor에서 직접 실행한다. 실행 후 `check_security.sql`.

## 5. 복구
| 상황 | 방법 |
|---|---|
| 배포 후 화면·기능 오류 | Netlify → Deploys → 직전 정상 배포 선택 → **Publish deploy**(즉시 되돌림). 이후 코드에서 `git revert`로 고쳐 다시 배포 |
| DB 함수를 잘못 바꿈 | 이전 버전 `sql/0X_*.sql`을 SQL Editor에서 다시 실행(모두 CREATE OR REPLACE) |
| DB 데이터 손상·삭제 | Supabase → Database → Backups(Pro: 매일 백업, PITR은 추가 옵션)에서 복원. Free 플랜은 백업 복원이 제한되므로 운영은 Pro 권장 |
| 서버 키(service_role/secret) 유출 의심 | Supabase에서 키 재발급(rotate) → Netlify 환경변수 교체 → 재배포. 활동 기록 확인 |
| 담당자 비밀번호 유출 의심 | 해당 계정 즉시 삭제 또는 비밀번호 변경 → 활동 기록에서 그 계정의 조회·다운로드 확인 |
| 슈퍼관리자 휴대폰 분실(OTP) | SQL Editor: `DELETE FROM auth.mfa_factors WHERE user_id = (SELECT id FROM auth.users WHERE email = '관리자이메일');` 실행 후 다시 로그인하면 QR 등록 화면 |
| 자동 파기 실패 반복 | [기록·파기]의 비고 확인 → Netlify Functions → purge 로그 확인 → [지금 실행] |
